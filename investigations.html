Account for every input row

The smaller scenario fixture deliberately includes duplicates and invalid rows. Strict mode rejects invalid input; partial loading requires an explicit flag.

15 input rows11 accepted alerts1 exact duplicate removed3 rejected with reasons

Malformed timestamps, unsupported severity values, and missing titles receive row-specific errors. Timestamps normalise to UTC. Duplicate removal compares every normalised alert field; distinct times and analyst context stay separate.

Run it yourself

From the repository root after installing the package in a virtual environment. The scenario command explicitly opts into partial loading because the fixture contains invalid rows.

python -m pip install .
python -m unittest discover -s tests -v
python scripts/validate_scenarios.py
python -m sentinel_soc_dashboard.cli \
  --alerts sample_data/investigation_scenarios.json \
  --skip-invalid --diagnostics input-quality.json

For PowerShell, enter the CLI command on one line. Open soc_report.html and compare its cases with input-quality.json.

Setup verified: a new Windows virtual environment, Python 3.12.14, a non-editable package install, and a CLI run outside the source tree without PYTHONPATH.

What this evidence does not establish

These tests verify defined behaviour on authored lab fixtures. They do not establish real-world detection accuracy, production readiness, or live Splunk / Microsoft Sentinel execution. Fixed windows can split related events; ATT&CK mappings are simplified; approved activity can still receive a high score.
